## Fixture scope and contract

PTR28_BASE v1 remains the data baseline in `tests/fixtures/ptr-28.ts`, now with a test-only `CalendarSource` adapter. Each case creates fresh arrays. Component tests inject that source; positive browser rendering tests intercept only the two availability reads. Authentication remains real. The application imports no test fixture.

Logical roles map to newly provisioned accounts for each real-auth case, rather than reusing the fixture's logical IDs as persisted IDs. Fixture venues, ownership and occupancy remain in memory; no test here establishes an event-to-booking database relationship.

The browser clock is fixed for fixture views. UTC+08:00, Asia/Singapore, all-day openings and the fixture adapter's no-hold policy are explicit test conventions. A browser configured for America/Los_Angeles still displays the supplied venue timezone. Product timezone, operating hours, adjacent-booking rules, pending holds and Technical Support Staff entitlement remain unresolved. Technical Support Staff has no availability grant pending confirmation.

The frontend sends `{ venueId, startDate, endDate }` with inclusive civil dates. The eventual server adapter owns conversion into actual instants and opening periods. Calendar controls use UTC only to represent civil dates. Response timestamps carry offsets, and the response supplies its display timezone. Runtime validation rejects malformed intervals, unknown timezones and responses for another selection.

TC06 overrides B01 to 10:15–11:45; an additional regression checks 10:15:30.125–11:45:42.750 without rounding. The combined TC05/TC06/TC11 browser test uses that override, so its pass verifies state labels and exact overridden times; it is not a literal replay of TC05's unchanged B01 baseline. Component and projection tests cover the baseline labels and periods separately. TC16 removes only its local bookings/blocks and supplies successful all-day openings. TC19 explicitly injects an error before a successful retry; a separate live browser test verifies that the unavailable backend exposes no fixture venues.
